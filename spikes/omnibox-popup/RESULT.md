# T0-4 検索候補の重ね表示の試作（R4）結果

## 2. 手順

### 準備（1回だけ）
1. `pnpm --dir spikes/omnibox-popup install`
2. `node spikes/omnibox-popup/node_modules/electron/install.js`（pnpm 12 では Electron 本体が自動で入らないため）

### 起動モード
| モード | コマンド | 候補一覧の出し方 |
|---|---|---|
| A overlay | `pnpm --dir spikes/omnibox-popup start:overlay`（`start` も同じ） | 専用の WebContentsView を最後に追加し、ページの上に重ねる |
| B push | `pnpm --dir spikes/omnibox-popup start:push` | 候補一覧が開いている間だけページを固定の高さ（8件分）下げ、空いた隙間に同じ View を置く |

- 画面は上から検索欄（灰色の帯）とページ（入力欄のある長い試験用ページ）。候補は入力から8件をその場で作る（通信しない）。選択中は黄色。
- メニュー「試作」: Cmd/Ctrl+S スクリーンショット（View ごとに `screenshots/raw/` に保存）、Cmd/Ctrl+Alt+1〜3 DevTools（検索欄・候補一覧・ページ）、Cmd/Ctrl+R 再読み込み、Cmd/Ctrl+Q 終了。
- `[spike] フォーカス: <名前>` で、どの View がフォーカスを受けたかが分かる。重なりの証拠は OS のスクリーンショット（macOS: Cmd+Shift+4 → Space）で撮り、`screenshots/raw/` に置く。

### 各モードでの確認（A → B の順。どちらも同じ手順）
1. モードのコマンドで起動し、`[spike] versions:` を 1章に転記する。起動直後の `[spike] フォーカス:` の最後が `input` であることを確認する。
2. すぐに検索欄へ `abc` と打つ。1文字ごとに候補が出て、中身が打った文字に合わせて変わるか（**入力中の候補の更新**）。ターミナルの `[spike] 候補の更新: xx ms` を、最初の1回と2回目以降に分けて 3章に転記する。
3. 候補一覧がページの文字に隠れず、上に出ているか（A）／ページが下がって隙間に出ているか（B）を見て、OS のスクリーンショットを撮る。
4. 下キーを3回、上キーを1回押す。黄色の選択が 1 → 2 → 3 → 2 行目と動き、ターミナルに `[spike] 選択:` が出るか。検索欄の文字カーソルが動かないか（**上下キーでの選択**）。
5. Esc を押す。候補一覧が消え、B ではページが元の位置に戻るか（**Esc で閉じる**）。
6. もう一度 `abc` と打って候補を出したまま、ウィンドウのタイトルバーをつかんで動かす。候補一覧が検索欄の真下についてくるか。次に、ウィンドウの右下をつかんで大きく・小さくする。候補一覧の幅が検索欄に合い、ずれたり取り残されたりしないか（**ウィンドウの移動・リサイズで位置がずれない**）。外部ディスプレイがあれば、ディスプレイをまたいで移したときも見る。
7. 候補を出したまま Enter を押す。ターミナルに `[spike] 決定:` が出て候補一覧が閉じ、そのまま検索欄に続けて打てるか。
8. ページの入力欄をクリックし、何か打つ。そのあと検索欄をクリックして `abc` と打つ。ページの入力欄に文字が入らず、候補が出るか。候補一覧の行をマウスでクリックしたあとも、検索欄に続けて打てるか（**フォーカスがページに奪われないか**）。
9. ページを下までスクロールしてから、手順 2〜5 をもう一度行い、表示が崩れないかを見る。
10. Cmd/Ctrl+Q で終了する。後片付けは、保存場所 `~/Library/Application Support/trueful-spike-omnibox-popup`（Windows: `%APPDATA%\trueful-spike-omnibox-popup`）を削除する。

## 付記: 開発環境での起動確認（2026-09-27、Claude Code）
- macOS（Apple Silicon）、Electron 44.4.5 / Chromium 152.0.7977.130 で両モードとも起動した。隠しオプション `--self-test`（例: `pnpm --dir spikes/omnibox-popup start:push -- --self-test`）で、検索欄に `abc` を打ち、下・下・上・Esc を送って終了する自動確認を行った。両モードとも、候補の更新・選択（0 → 1 → 0）・Esc で閉じるがログのとおりに動いた。
- 候補の更新にかかった時間は、最初の1回が 10〜40ms（6回の実行）、2回目以降が 1ms 前後だった（Main が入力を受けてから、候補一覧の描画後の知らせを受けるまで）。最初の1回は隠していた View を表示するぶん遅く、16ms の予算を超えうる。本体では、候補一覧の View を先に表示しておく等を検討する。候補一覧を表示しても、候補一覧に `focus` イベントは出なかった。
- 起動直後、3つの View はそれぞれ読み込み時に1回ずつ `focus` イベントを受ける。検索欄に先にフォーカスを当てると、あとから読み込みを終えたページに奪われ、最初の1文字が失われた。このため、3つの読み込みを待ってから検索欄にフォーカスするようにした。本体でも、ページの読み込みでフォーカスが奪われないかを確かめる必要がある。
- ウィンドウの移動・リサイズ、マウス操作、見た目は自動では確かめていない。
